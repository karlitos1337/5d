## 2024-05-16 - Cached DOM lookups in scroll listener
**Learning:** In React components with custom scroll implementations, repeatedly calling `document.getElementById()` inside a continuous `scroll` event handler can cause layout thrashing and block the main thread, especially on long pages with many tracked sections. Furthermore, duplicate static object/array allocations inside the functional component body (like a `sections` array) causes unnecessary re-allocations on every render.
**Action:** When implementing custom active-section tracking via scroll events, cache the DOM elements outside the event listener loop (e.g., in the setup phase of the `useEffect`) to prevent expensive repeated queries. Hoist static arrays outside the component definition to avoid re-allocations.
